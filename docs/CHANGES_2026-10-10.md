# Изменения 10.10.2026 и как ими пользоваться

Доработки по замечаниям преподавателя:

1. Отладка: точка останова на строку кода, просмотр переменных.
2. Единообразная навигация (раньше были Open project, Open folder и т. д.).
3. Компиляция с оптимизацией и выбор уровня.
4. Настройка тактирования шин, как в CubeMX.

Коммит `9a48836` в ветке `my-version`. Подробности по файлам — в [CHANGELOG.md](../CHANGELOG.md),
раздел «Доработки по замечаниям преподавателя». Полный чек-лист проверки —
[MANUAL_TESTING.md](MANUAL_TESTING.md), разделы 15–18.

## 1. Отладчик по исходному коду

### Что это
Отладка устроена так же, как в STM32CubeIDE с ST-LINK: в эмуляторе работает GDB-сервер, а после
**Build & Load** программа сама запускает `arm-none-eabi-gdb` из тулчейна и подключает его к
эмулятору. Ничего настраивать не нужно.

Состояние отладчика видно в заголовке панели **Debug** (справа): `gdb · stopped`,
`gdb · running` или `no session`.

### Как пользоваться
1. Открыть проект и нажать **Build & Load** (Ctrl+B).
2. Поставить точку останова: **кликнуть по номеру строки** в редакторе или поставить туда курсор
   и нажать **F9**. Появится красная точка. Ещё один клик или F9 — точка снимается.
   - Если на строке нет кода (пустая строка, комментарий), точка переедет на ближайшую строку с
     кодом. Если кода нет совсем — серый кружок, причина видна на вкладке Breakpoints.
   - Точки можно ставить и во время работы программы: отладчик сам ненадолго остановит её,
     поставит точку и продолжит.
3. **Run** (F5). Программа остановится на точке: жёлтая стрелка и подсветка строки, редактор сам
   откроет нужный файл.
4. Дальше — шаги:

   | Кнопка | Клавиша | Что делает |
   |---|---|---|
   | Run | F5 | продолжить до следующей точки останова |
   | Pause | Shift+F5 | остановить там, где сейчас программа |
   | Step Over | F10 | следующая строка, вызовы функций выполняются целиком |
   | Step Into | F11 | следующая строка с заходом в вызываемую функцию |
   | Step Out | Shift+F11 | выполнить функцию до возврата из неё |
   | Step Instr | Ctrl+F10 | одна машинная инструкция |
   | Reset | Ctrl+Shift+F5 | перезапуск МК, точки останова остаются |

   Step Into не заходит в библиотеки HAL, CMSIS и FreeRTOS — только в код проекта.

### Панель Debug
- **Variables** — локальные переменные текущей функции и глобальные/статические переменные
  файлов проекта.
  - ▸ раскрывает структуры и массивы.
  - **Красным** выделены значения, изменившиеся с прошлой остановки.
  - **Двойной клик по значению** — изменить его (программа увидит новое значение).
  - Галочка **Hex** — показывать числа в шестнадцатеричном виде.
- **Watch** — любые выражения на C: `counter`, `values[2]`, `p.x * 2`, `GPIOD->ODR`. Ввести в
  поле и нажать Enter; × удаляет выражение.
- **Call Stack** — цепочка вызовов. Клик по строке показывает место вызова в редакторе и
  переменные этой функции.
- **Breakpoints** — список всех точек; × удаляет одну, **Delete all** (Ctrl+Shift+F9) — все.
  Здесь же можно поставить точку **по адресу** (например `0x08000200`) — так работает и для
  прошивок без отладочной информации (демо-прошивка, BIN, HEX).

### Отладка с оптимизацией
С `-O2` и `-Os` отладчик тоже работает, но часть переменных будет показана как
`<optimized out>`, а неиспользуемые переменные компилятор может убрать совсем. Это нормально, так
же ведёт себя CubeIDE в конфигурации Release. Для отладки удобнее всего `-O0` или `-Og`.

### Если отладчик не запускается
Перед запуском `mk_emul.exe` задать переменную окружения `MK_EMUL_GDB_LOG=C:\путь\gdb.log` —
в этот файл запишется весь обмен с gdb.

## 2. Меню и навигация

### Что изменилось
Все действия собраны в строке меню **File / Build / Debug / View** (открывается и с клавиатуры:
Alt+F, Alt+B, Alt+D, Alt+V). У каждого действия одно название везде — в меню, на кнопке, в
подсказке — и своё сочетание клавиш, оно написано в меню справа.

Убрано: кнопка «Open folder…» в панели Source (она делала то же, что Open project), кнопки
Builtin LED / Open FW… / Open project… на панели инструментов, поле BP. Панель инструментов
теперь только для запуска, отладки и сборки.

### Меню

| Меню | Пункт | Клавиши |
|---|---|---|
| File | New Project… — создать проект в пустой папке (с готовым `main.c`) | Ctrl+N |
| | Open Project… — открыть папку проекта | Ctrl+O |
| | Open Example ▸ — любой пример из `examples/` | |
| | Recent Projects ▸ — недавние проекты | |
| | Save All | Ctrl+S |
| | Open Firmware… — готовый ELF / HEX / BIN | Ctrl+Shift+O |
| | Load Demo Firmware — встроенная мигалка | |
| Build | Build & Load | Ctrl+B |
| | Optimization ▸ — уровень оптимизации | |
| | Clock Configuration… — тактирование | |
| Debug | Run / Pause / Reset, шаги, точки останова | см. таблицу выше |
| View | Go to Line… — перейти к строке | Ctrl+G |
| | Expand Editor — редактор на всё окно | Ctrl+M |

Ещё:
- при запуске открывается **последний проект**;
- регистры CPU и периферия — две вкладки одной панели слева внизу;
- **F11 теперь Step Into** (как в Visual Studio), редактор разворачивается по **Ctrl+M**.

## 3. Оптимизация

### Как пользоваться
Выбрать уровень в выпадающем списке рядом с **Build & Load** или в **Build → Optimization**, затем
нажать Build & Load. Выбор сохраняется между запусками.

| Уровень | Когда использовать |
|---|---|
| `-O0` | без оптимизации, лучший вариант для отладки (Debug в CubeIDE) |
| `-Og` | оптимизация, при которой удобно отлаживать |
| `-O1` | базовая оптимизация |
| `-O2` | по скорости (типичный Release) |
| `-O3` | максимальная скорость |
| `-Os` | по размеру (Release в CubeIDE) |

В логе сборки видно выбранный уровень и размер прошивки:
```
Optimization: -Os
Size (-Os): flash 7436 bytes, RAM 1728 bytes (static)
```
Для `hal_blinky`: `-O0` — 11180 байт flash, `-Og` — 8160, `-O1` — 8064, `-O2` — 7620,
`-O3` — 8064, `-Os` — 7436.

Библиотеки (HAL, FreeRTOS) собираются с тем же уровнем и кешируются отдельно для каждого, поэтому
переключение туда-обратно не пересобирает HAL заново.

## 4. Тактирование (Clock Configuration)

### Как открыть
Кнопка **Clock…** на панели инструментов или **Build → Clock Configuration…**.

### Что в окне
Дерево тактов STM32F407, как вкладка Clock Configuration в CubeMX:
- источники: **HSI** 16 МГц и **HSE** 8 МГц (кварц платы Discovery);
- **PLL Source** — откуда PLL берёт частоту;
- **/M**, **×N**, **/P**, **/Q** — делители и множитель PLL;
- **System Clock Mux** — источник SYSCLK: HSI, HSE или PLLCLK;
- делители **AHB**, **APB1**, **APB2** и итоговые частоты: HCLK, шины APB1 и APB2, таймеры на них
  (таймеры получают ×2, если делитель шины не 1), выход 48 МГц для USB/SDIO/RNG;
- **Flash latency** — сколько тактов ожидания flash нужно при такой частоте.

Ограничения проверяются сразу. Если что-то превышено (SYSCLK больше 168 МГц, APB1 больше 42 МГц,
APB2 больше 84 МГц, VCO вне допустимого диапазона…), значение красное, а внизу написано, что не
так. Жёлтым — предупреждения: схема работает, но не как рекомендовано (например, на выходе 48 МГц
не ровно 48 — USB так работать не будет).

Кнопки-пресеты: **168 MHz (HSE+PLL)**, **84 MHz (HSI+PLL)**, **16 MHz HSI (reset)**.

### Как получить код
- Вкладка **Generated code** — готовая функция `SystemClock_Config()` с комментарием, где
  перечислены все частоты. Для HAL-проекта она через `HAL_RCC_OscConfig` /
  `HAL_RCC_ClockConfig`, для регистрового — напрямую через регистры RCC, FLASH, PWR.
- **Copy Code** — скопировать в буфер обмена.
- **Write to Project** — записать в проект:
  - если в проекте уже есть `SystemClock_Config()` (как в `main.c` от CubeMX), она заменяется;
  - если нет — добавляются файлы `clock_config.c` и `clock_config.h`. Тогда в `main.c` нужно
    добавить `#include "clock_config.h"` и вызвать `SystemClock_Config();` в начале `main()`.

  Если в настройке есть ошибки (красное), кнопка недоступна.

### Как проверить, что прошивка выставила нужные частоты
Под каждой частотой написано **emulator: N MHz** — это то, что настроила работающая сейчас
прошивка. Если совпадает с выбранным в окне — строка зелёная.

**From Emulator** переносит в окно настройки, которые сейчас стоят в эмуляторе.

Пример:
1. File → Open Example → `hal_blinky`.
2. Clock… → **84 MHz (HSI+PLL)** → **Write to Project** → Close.
3. Build & Load → Run.
4. В консоли UART: `HAL ok, SYSCLK=84000000`, строки `tick` идут как раньше; в окне Clock… все
   строки «emulator» зелёные.

Настройки окна сохраняются отдельно для каждого проекта.
